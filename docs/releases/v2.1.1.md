# SC2AM v2.1.1

**Release candidate — Unreleased.** This compatible patch follows v2.1.0.
The [GitHub release](https://github.com/zFl4wless/sc2am/releases/tag/v2.1.1)
is the publication record; use the wheel below only after its asset is visible.

## What changes for users

- New imports remove pre-existing SC2AM source markers from all ID3 comment
  texts, including embedded markers and uppercase/mixed-case ASCII variants.
  Ordinary comments remain, and one canonical marker identifies the current
  source. Repeating marker preparation produces the same file bytes.
- Repeat/resume resolves the active Music library before consulting its saved
  track reference. A valid saved ID takes precedence over conflicting or
  ambiguous comment markers. Missing references still use the existing fallback
  lookup; unresolved mutations are not blindly repeated.
- Project documentation clarifies the current CLI and MP3 workflow. Optional
  clipboard entry points and additional output formats remain deferred.

Python 3.10+, configuration keys and dependency minimums are unchanged. A fresh
successful playlist import adds one read-only Music lookup per track; successful
resume retains the previous process count. No cloud-sync speed claim is made.

## Upgrade

After publication, activate your existing SC2AM environment and run:

```bash
python -m pip install --upgrade \
  "https://github.com/zFl4wless/sc2am/releases/download/v2.1.1/sc2am-2.1.1-py3-none-any.whl"
python -m pip check
sc2am doctor
```

Keep your configuration, downloads and `<download_dir>/.sc2am/history.sqlite3`.
Do not remove the journal to retry an uncertain Music import. No configuration
migration or library cleanup is required by this patch.

## Scope and verification limits

The functional change is [PR #124](https://github.com/zFl4wless/sc2am/pull/124),
merged at `a9e933a8624db61ae688c88651e59878010ed9f0`. Other changes since v2.1.0
are presentation and exploration documentation in PRs #121–#123.

Synthetic regression tests cover ID3 comment preservation, ASCII case variants,
repeated preparation, saved-ID precedence, ambiguous fallback matches, library
changes, history refresh and interrupted mutation recovery. Package checks verify
version/license metadata and installed CLI behavior outside the checkout.

Existing Music entries are **not retroactively cleaned**. This is track-association
hardening, not a confirmed remote-vulnerability fix. Provider delivery of prepared
comments and native Music comment matching remain unverified. Artwork/media
network questions from the static review remain unresolved; this patch does not
change their policies or claim to close them.

No new live Music, cloud, iPhone or CarPlay acceptance was performed. The
[v2.1.1 acceptance record](v2.1.1-acceptance.md) marks these scenarios NOT TESTED.
The earlier v2.1.0 device record is historical evidence, not a new validation of
this changed implementation.
