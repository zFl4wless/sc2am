# SC2AM v2.1.0

Release notes dated **2026-10-08**. The [GitHub release and assets](https://github.com/zFl4wless/sc2am/releases/tag/v2.1.0)
are the publication record. Use the installation links below only once those
assets are visible; version metadata and this dated entry alone do not confirm
publication.

This compatible minor release combines the completed reliability fixes planned
for v2.0.2 with the v2.1.0 features. **v2.0.2 is skipped**, not retrospectively
released; its fixes ship in v2.1.0. The full user-facing entries are in the
[changelog](../../CHANGELOG.md#210---2026-10-08).

## What changes for users

- Repeat a download or batch command in the same download directory to reuse
  the verified MP3. SC2AM records file hashes and source identities and checks
  Music's active library and playlist membership before importing again.
  Uncertain previous Music mutations are reconciled or stopped for manual
  recovery; successful command dispatch alone no longer proves import success.
- Read download, confirmed import and playlist outcomes separately. Music
  failures remain warnings by default. Add `--strict-import` to return exit 1
  for failed/unconfirmed Music stages; combine with `--continue-on-error` to
  continue processing later tracks after those failures.
- Run `sc2am doctor` to check prerequisites without writing files, downloading
  audio, invoking Music or changing the library. It does not verify Automation
  permission, cloud sync or device playback.
- Paste mobile `on.soundcloud.com` share links into `download` or `batch`.
  Resolution is bounded and rejects unrelated hosts, loops and collections;
  share-link dry runs need a network connection. Direct track URLs still
  validate locally.
- Use playlist/path names with commas, quotes or Unicode. Duplicate playlist
  names and Smart/Genius/folder/system targets are rejected with guidance.
  Music subprocesses have bounded timeouts and only safe read queries retry.
- Get actionable diagnostic instructions and validated, bounded artwork
  downloads with JPEG normalization and a reported fallback. The already
  checked extraction and playlist target are reused to reduce repeated work.
- Follow the [Mac-to-iPhone/offline/CarPlay guide](../macos-setup.md) and watch
  the [36-second animated overview](../demo/product-film/README.md).

Python 3.10+ remains supported. This release adds Pillow and raises the minimum
Click, idna and urllib3 versions; runtime dependency auditing, application type
checks and MIT SPDX/license-file checks are part of CI. It introduces no new
configuration-key removal. Default configuration precedence and download-based
exit status remain compatible; strict Music status is opt-in.

## Upgrade

Once the v2.1.0 wheel is published and visible on GitHub, run the following
in the same activated virtual environment used for SC2AM. See the
[README installation guide](../../README.md#end-user-installation-on-macos) for a new environment:

```bash
python -m pip install --upgrade \
  "https://github.com/zFl4wless/sc2am/releases/download/v2.1.0/sc2am-2.1.0-py3-none-any.whl"
python -m pip check
sc2am doctor
```

Keep your configuration, MP3s and `<download_dir>/.sc2am/history.sqlite3` together.
The journal is created as needed; do not delete it to retry an uncertain import.
Safe reuse/resume is scoped to that download folder. Changed cached files stop
with an integrity warning; missing files can be downloaded again. There is no
automatic migration of old title-only filenames. Imports from earlier versions
can be recognized by their original file location; copied legacy imports without
a marker/history need manual review before the first run. Follow
[Music import recovery](../music-import-validation.md) for unresolved operations.
Do not run concurrent imports from different download folders into one library.

If upgrading from before v2.0.0, the settings removed in **v2.0.0** still need
manual correction; see its [changelog entry](../../CHANGELOG.md#200---2026-10-01).
Back up the config before `sc2am config init --force`, which replaces that YAML
file only. The upgrade does not remove downloaded tracks or the resume journal.

The [2026-10-08 record](../demo/device-acceptance-2026-10-08.md) reports **13 PASS
and 1 Finder N/A**. It documents direct Mac observations of tags/artwork,
confirmed imports, repeated/batch URLs, unusual playlist names, missing
prerequisites/Automation permission, a controlled real-transfer interruption
and retry, and a fully decoded/imported 20-minute track.

The Mac cloud upload was first observed complete at 48.539 seconds, an upper
bound to observed completion. iPhone 13 / iOS 27.0.1 appearance, downloaded
offline playback and parked wireless BMW CarPlay results are **owner-reported**;
they were not independently observed or filmed. Exact phone arrival time and
vehicle model were not supplied. Finder sync, natural network outages and the
long track's cloud/device route were not tested. Setup exceptions (existing
local fixtures, no disposable macOS user, personal account expressly authorized
for the one-track cloud test) remain in the original record.

`1a168c31fdd087a870f62d39c815075441294d68`; README follow-up #118 was merged at
`c55a30e39fe92c008440617f35fd47b8ff9aa87b`. The owner accepted the animated

phone/car scenes are illustrations and the soundtrack is not playback evidence.

SC2AM confirms the local Mac library only. It does not automate, guarantee or
time iPhone/cloud synchronization. No new personal-library, account, device,
sync or Automation changes are part of release preparation.
